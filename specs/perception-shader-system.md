# Paradox Engine + BNTL Core — Perception Shader System

This spec prevents the visual system from being narrowed into only hazards, warnings, weather, or emergency monitoring.

## Core Correction

The visual system is not just a warning system.
It is not just a weather system.
It is not just a hazard display.
It is not just a dashboard for alerts.

It is a real-life perception shader system.

Paradox Engine + BNTL Core should help people perceive different layers of reality by using shaders, colors, overlays, motion systems, symbolic filters, source-driven Visions, and interaction modes.

The system should transform incoming feeds and real-world inputs into visual perception layers that make hidden, scattered, subtle, or complex signals easier to sense, understand, compare, and act on.

## Product Meaning

The purpose is not only to warn users that something is wrong.

The purpose is to reveal what is present.

The system should help users perceive:

- environmental conditions
- energetic patterns
- signal fields
- source freshness
- trust and uncertainty
- relationships between domains
- hidden or subtle changes
- resonance and alignment
- motion in real-world systems
- device/local context
- symbolic and mythic layers where appropriate
- operational readiness
- action boundaries

Warnings are only one category of perception.

## Vision + Shader Principle

Every feed or input can become a Vision.
Every Vision can have one or more shaders.
Every shader should help the operator perceive something specific.

A shader is not decoration.
A shader is a perception tool.

Each shader must answer:

1. What does this help the user perceive?
2. What data/source/condition drives it?
3. What colors, motion, texture, or geometry represent it?
4. What does a change in the shader mean?
5. How does it connect to RealitySignal, FRG, What Happened, Source Health, State Core, Director, Codex, and Safety/Provenance?

## Visual System Categories

### 1. Spectrum / Signal Shaders
For perceiving waveforms, frequencies, signal fields, RF-like behavior, electromagnetic-like interpretation, Wi-Fi echo concepts, resonance, interference, or measurement-derived fields.

Possible language:
- arcs
- interference fringes
- ribbons
- wavefronts
- pulse fields
- distortion bands
- scan lines
- frequency gradients

### 2. Environmental Shaders
For perceiving atmosphere, weather, ocean, seismic, air quality, geomagnetic, solar, radiation, volcanic, or other natural/environmental conditions.

Possible language:
- haze fields
- cyclone motion
- wave bands
- aurora curtains
- seismic ripples
- solar streams
- pressure ribbons
- thermal blooms

### 3. Spatial / Geometry Shaders
For perceiving depth, contours, surfaces, edges, topology, location masks, trajectory, proximity, or structure.

Possible language:
- edge glow
- contour lines
- depth meshes
- normal-aware overlays
- route paths
- orbital grids
- topology cells
- spatial masks

### 4. Cognitive / Emotional / Human-Layer Shaders
For perceiving human-state, attention, stress, fatigue, cognition, emotional tone, creative state, coherence, or human/device interaction patterns where permitted and ethically handled.

Possible language:
- rhythmic rings
- pulse halos
- fatigue banners
- coherence waves
- attention focus glow
- stress modulation
- emotional tone tint

### 5. Mythic / Symbolic / Meaning Shaders
For symbolic interpretation, mythic layer, resonance, archetype, alignment, destiny/world/cycle anchors, or narrative meaning overlays.

Possible language:
- violet/magenta resonance lines
- sigil-like relationship marks
- symbolic gates
- orbiting meaning nodes
- cycle rings
- alignment arcs

### 6. Operational / Trust Shaders
For perceiving source health, freshness, confidence, provenance, safety state, permission state, agent mode, and action readiness.

Possible language:
- green/yellow/red trust glow
- stale dimming
- blocked-action red edge
- provenance seal shine
- Codex mark
- safety gate ring
- MONITOR blue wash
- ENGAGE red boundary

### 7. Relationship / FRG Shaders
For perceiving how things connect, influence, relate, or become part of a symbiosis chain.

Possible language:
- relationship strands
- node links
- fusion bridges
- bounded influence lines
- candidate chain glow
- corroborated chain highlight
- validation-required dashed lines

## Important Distinction

A warning says: something needs attention.

A perception shader says: here is a layer of reality you can now sense.

Both can exist, but warnings are only one outcome.

## Design Rule

Do not reduce the visual system to hazard states.

Every Vision should be designed as a perceptual lens.
Every shader should reveal a dimension of the real world, system state, human layer, symbolic layer, or relationship layer.

## UI Rule

The main screen should not lead with raw stats.

The main screen should show the active perception scene:

- what layer is active
- what the operator is perceiving
- what is changing
- where it comes from
- how trustworthy it is
- how it relates to other layers
- what can be explored next

Numbers and technical details belong in drawers, Source Health, Director, OS Core, Codex, or detail panels.

## Final Definition

The Perception Shader System is the visual language of Paradox Engine + BNTL Core. It turns feeds, states, relationships, attachments, and real-world interactions into living visual layers that help users perceive more than normal dashboards can show.
