# BNTL Core · Paradox Engine — Visual Quality Guard

This guard protects the product from losing structure or drifting into generic AI-slop aesthetics.

## Core Standard

BNTL should feel like a custom human-directed operating system for perception, understanding, correlation, and action. It should not feel like a generic AI dashboard template.

## Structural Integrity Rules

- Preserve the master modules: Command Home, What Happened, FRG Core, HUD, Live Feed, Visual Layers, Atlas, Planetary System, Sources, Source Health, Events, Workers, Worker Sync, Validation, Technical Backbone, Coverage Audit, Feedback, and Operator Panel.
- Preserve the backend record families: workers, modules, sources, connectors, events, EventEnvelope records, validation notes, tasks, feedback, coverage, activity, FRG nodes, FRG relationships, and artwork layers.
- Preserve the live/source lanes and operational statuses.
- Preserve navigation: large module buttons, working tabs, All Systems drawer, mobile nav, filters, detail drawers, and accessible focus states.
- Preserve the relationship between idea, system, image direction, and working product.

## Anti AI-Slop Rules

Avoid:

- random neon clutter
- generic sci-fi card grids
- fake-looking data blocks
- meaningless animated rings
- overused AI orb layouts
- dense unreadable text walls
- decoration that does not connect to system behavior
- inconsistent icons or spacing
- oversized empty panels
- copy that sounds like a prompt rather than a product
- tabs or controls that look clickable but do nothing

Require:

- believable product UI
- strong hierarchy
- intentional spacing
- consistent components
- readable typography
- restrained motion
- real module depth
- source/status truth
- meaningful visual-system links
- human-led design taste
- clear correlation from the original BNTL idea to the product screen

## Visual North Star

The reference image should be treated as a north star for structure and intent, not something to copy blindly.

Keep:

- left operating-system sidebar
- central relationship/perception engine
- right HUD and system utility panels
- lower narrative flow from human view to system processing to real-world action
- live status / system health feeling
- AJ / human-led identity presence
- dark premium command-center atmosphere

Improve:

- make it less generic
- make it more BNTL-specific
- make it more usable
- make every module interactive
- make every visual connected to a record, source, event, worker, or relationship
- make the app feel operational instead of poster-like

## Design Language

The design should feel:

- premium
- custom
- serious
- cinematic
- human-directed
- structurally sound
- alive but not chaotic
- complex but navigable
- philosophical but practical
- technical but readable

## Correlation Rule

Every new screen or visual layer must answer:

1. What idea does this represent?
2. What module does it belong to?
3. What record or source powers it?
4. What user action does it support?
5. How does it connect back to FRG Core and What Happened?

If it cannot answer those questions, it should not be added.

## Upgrade Rule

Every future Lovable/design pass must upgrade visuals and module depth without removing structural integrity. Improve taste, realism, and interactivity while preserving the complete BNTL backbone.
