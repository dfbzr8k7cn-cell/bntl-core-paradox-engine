# BNTL Core · Paradox Engine — Network Art + Status Color Language

This spec defines how the visual network/artwork should behave and how status color should read across the app.

## Status Color Semantics

Use familiar operational color meaning:

- Green = connected, active, healthy, updated, available
- Yellow / Amber = caution, pending, stale, needs review, awaiting first fetch
- Red = not connected, error, failed, blocked, unavailable
- Blue / Cyan = live signal, neutral system activity, scan, source flow, default HUD energy
- Violet / Magenta = FRG relationship, resonance, perception layer, symbolic/deeper system identity
- White / Soft gray = labels, structure, inactive interface lines

Do not make color the only meaning. Always pair status color with text labels and accessible contrast.

## Network Artwork Direction

The visual network should be a real design system, not random decorative lines.

It should show:

- source nodes
- event nodes
- visual layer nodes
- worker nodes
- module nodes
- planetary nodes
- device nodes
- validation nodes
- feedback nodes
- system status nodes

Connections should represent actual relationships:

- source feeds module
- source updates visual layer
- event feeds What Happened
- event connects to FRG Core
- worker updates build lane
- connector health affects module status
- device state feeds local pulse
- validation supports confidence
- feedback affects review queue

## Artwork Style

Keep the cool space-art direction:

- cosmic starfield
- orbital grid
- nebula depth
- scan rings
- aurora arcs
- solar streams
- planetary orbits
- seismic ripples
- weather swirls
- ocean bands
- aviation paths
- air-quality haze
- device pulse
- worker-grid pulse

But make the layout controlled and intentional.

Avoid:

- random lines that do not mean anything
- generic neon dashboards
- overdone AI-glow orbs
- chaotic unreadable webs
- meaningless particles
- fake charts
- trashy sci-fi clutter

Require:

- readable node hierarchy
- meaningful connections
- clear status color
- real module linkage
- tasteful motion
- premium spacing
- consistent visual grammar
- direct correlation to BNTL concepts

## BNTL Network Personality

The network should feel like:

- perception becoming structure
- data becoming understanding
- source signals becoming relationships
- relationships becoming action
- human direction plus system intelligence

It should look like AJ's BNTL system, not a stock AI dashboard.

## Interaction Rules

- Hover or tap a node to show source/module/status.
- Click a node to open its drawer.
- Click a connection to show relationship details.
- Filter by category: Earth, Weather, Ocean, Cosmic, Planetary, Aviation, Air Quality, Device, Workers, Validation.
- Status color must update with the node state.
- Lines should pulse only when activity is recent.
- Inactive systems should stay visible but subdued.

## Correlation Rule

Every visual line or node must connect back to at least one of:

- source record
- event record
- FRG relationship
- module record
- worker record
- visual layer record
- source health state
- What Happened item

No orphan artwork.
