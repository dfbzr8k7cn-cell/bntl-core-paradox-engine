# Work Allocation + Integration Plan

This plan prevents the project from bottlenecking on a single app or single prompt. Each tool has a limited role. All work feeds back into the same Paradox Engine + BNTL Core master system.

## Master Rule

No app becomes the project.
No app replaces the source of truth.
No tool bottleneck stops the project.
No output is accepted unless it preserves the additive full-blend ledger.

## Current Main Lane

### Current visual app lane
Use the current app builder lane to keep the running visual HUD moving.

Purpose:
- visual exploration
- interactive shell iteration
- template fidelity checks
- quick UI review

Limits:
- do not rely on it for pixel-perfect final implementation
- do not overload it with all architecture at once
- do not treat it as the only build lane

### GitHub
