# Additive Upgrade / No-Cut Rule

This rule is absolute for Paradox Engine + BNTL Core.

## Core Rule

We are not taking anything away.
We are not simplifying by deleting.
We are not downgrading.
We are not making shortcuts.
We are not flattening AJ's work into a smaller generic version.

We are assembling the full system that already exists in concept and upgrading execution, fidelity, usability, backbone, and visual quality.

## What Upgrade Means

Upgrade means:

- preserve every core layer
- preserve every named module
- preserve the locked visual template
- preserve the BNTL spine
- preserve Vision OS
- preserve Director
- preserve State Core
- preserve Ghost AI
- preserve Apex Infinite
- preserve attachments
- preserve Codex
- preserve safety/provenance
- preserve agent modes
- preserve source/adapter lanes
- preserve meaningful network artwork
- preserve all current user-friendly improvements

Then improve:

- visual fidelity
- interaction quality
- module depth
- backend wiring
- live data behavior
- accessibility
- operational realism
- status truth
- performance
- validation

## No-Cut Interpretation

If a part feels too complex, do not remove it.

Instead:

- organize it
- place it in the correct rail, dock, panel, drawer, mode, tab, or operator view
- improve hierarchy
- improve navigation
- make the relationship clearer
- make the visual less cluttered
- preserve the function

## Layering Rule

Depth is not clutter when it is layered correctly.

Use:

- left rail
- top module dock
- central RealitySignal / Perception hub
- right rail
- active gates row
- cinematic strip
- bottom panels
- drawers
- tabs
- filters
- Operator Panel

Do not solve complexity by deleting the system.

## Merge Rule

The prior transfer summary and the current chat work must be merged additively.

Do not choose between them.

The correct system is:

Locked BNTL template + live perception OS + Vision OS + State Core + Director + Ghost AI + Apex Infinite + Attachment Stack + Codex + Safety/Provenance + current interactive usability + meaningful network artwork + real source lanes.

## Final Test

Before any build pass, ask:

1. Did we remove anything AJ said was part of the system?
2. Did we downgrade a concept into a generic card?
3. Did we hide the identity to make the UI easier?
4. Did we keep the template structure?
5. Did we upgrade the execution instead of cutting the idea?

If any answer is wrong, the pass fails.
